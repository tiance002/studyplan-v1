# v6.12 审阅裁决：保留教学设计，修复派发—恢复—保存合同

日期：2026-10-04。本文为基于附件证据的设计评审，不是对未提交候选源码的独立运行验收。

## 1. 当前成果应怎样定性

教学样本已经具备用户反复确认的主要结构：A0–A8（含 Framework、MCP 与 Pi whole_core）→ G0–G6 详细 RAG 教程 → GR 成熟工程选定切片 → GT 迁移验证。样本有18阶段、16 canonical、18正式任务；A2有3个 LearningUnit，关联同一个 canonical，仍只有1个正式任务。

这证明本轮的 Fake/owned PG 样本已经表达分段教学，不证明真实模型生成成功、真实学习者掌握或整产品 READY。来源：计划 §本次实际教学顺序、§A2；实施报告 §实施候选。

16 canonical 对18阶段本身不是缺陷：样本的 G6/GR/GT复用同一个知识身份，学习出现位置与任务不同。不能为了让数字相等复制概念或继承上一位置的完成状态。

完整验收仍缺实际持久化 Plan 的 Edge 消费。Edge+Mock 与 owned PG 两段各自通过，不能相加称同一端到端链通过。来源：实施报告 §验证与用量；31项验收 U09/R02/P01/P02。

## 3. F1 的方案选择

推荐“**从独立绑定的冻结来源重建 → 比对 → 不一致拒绝保存**”，而不是默默覆盖篡改再报通过。

需要区分：

- 独立可信基准：已有服务端 Run/Job 冻结输入、绑定的来源快照/摘要、运行身份与合同版本；不是从待校验 checkpoint 里同时取内容和预期hash自证。
- 原始生成证据：原请求/原响应及其现有持久化绑定。模型内容仅在声明的呈现范围内使用，不成为canonical。
- 派生状态：规范化batches、顶层nodes/units/relations/practice_proposal及教学rubric；均可重建，也均需校验。
- 用户合法编辑：由已有草案/变更版本与明确操作身份授权；不能因为重建初始生成结果而覆盖。

从冻结canonical与重新验证的原始presentation重建规范化结构，再用既有merge构成待保存投影；检查所有实际进入业务持久化的受保护字段。仅比较structure_batches不足；直接信任checkpoint中的normalized batch也不足。

复用一个纯重建/比较实现，在恢复入口与实际应用保存入口调用。保存前取得独立基准、构造不可被后续共享state变更的验证副本，并让已有事务持久化同一份内容。保留现有锁顺序、owner/RLS、取消/租约/幂等检查，不新建publisher或安全平台。

默认不一致产生确定性错误、保留证据、阻止Draft/Plan与相关业务内容写入；审计/失败状态记录允许按已有契约保存。允许在正常生成路径回填模型不能决定的canonical，不允许在发现恢复篡改时静默“修好即成功”。

## 4. F2 的最小可实现边界

不要再次依靠“全段文本出现某词=允许教学/实现”。对于本阶段实际选择的focus refs，明确正向能力与允许意图（解释/比较/练习）以及排除事实。比较一种技术不等于要求部署该技术；禁止句不是许可来源。

内部派生focus映射可复用现有JSON/冻结对象，不新增公开API。只校正有明确证据的映射规则与反例，不尝试写通用自然语言理解器。

生成单元不能改变正式任务、验收、前置与付费/外部副作用授权。文本过滤只对明确已覆盖的越界模式声明有效，不宣称理解了所有中文/英文否定句。对真实模型单元仍做有界人工/评审者内容审查；合法ref不是教学正确性的证明。

## 5. F3 的最小可实现边界

普通输入上界、模型输出对象上界、repair输入上界要分别计算。repair输入预算来自：实际repair system/schema/envelope + 原局部context + 有界失败对象 + 有界字段错误。

保持完整、有界的失败对象，不把相同普通输入ceiling同时当输出与repair ceiling。不发整包、不截断原证据、不放宽provider输出cap、全Run请求上限或2次repair。

派发前确定性拒绝不得计作真实provider请求，也不得伪装已发生一次模型repair。先做本地预检；实际派发/unknown仍按原账保守计量。本地拒绝不得自动进入无限构建重试。历史错误计数不改写。

## 6. F4 的最小可实现边界

合同类型依据服务端冻结记录与完整标记组合，而不是一个可缺省字段。外层、focus、per-batch、hash与pack绑定必须一致。真正无新合同的历史Run保留legacy；已有短outline但旧structure的合法历史也不应被误拒绝。

需要识别残留标记及unknown version。即使攻击性测试删除所有checkpoint新marker，只要服务端该Run原冻结为新合同，就不能退回legacy。检查发生在provider/Fake派发前，而不只靠后续merge兜底。

## 7. 教学样本中另外两项表达观察（不是重构任务）

- A7 单元目标目前直接重复“A7 系统评价”；已有canonical其实提供了更有意义的能力目标。来源：样本 §A7。
- A8 的说明中“只读已审SDK与Sessions文档边界”，与任务/Prompt要求“沿当前源码定位”容易产生误解。应区分“资料审核深度”与“学习时外部AI可读当前源码”，不把未深审全仓理解为禁止源码学习。来源：样本 §A8。

这两项可先记为体验文字待优化，不能借机改动已冻结历史Plan或扩大新课程。若仅为无语义变化的展示整理可顺带处理；若涉及canonical/内容版本变化，按既有新版本规则单独列明，不以此拖延F1–F4。

成熟项目metadata_only应如实保留：它可以是需要在学习时核验适合性的参考候选，不能冒称全仓已审。用户最终需要亲自确认这份路线的可读性；自动测试不能代替。

## 8. 收口顺序

保存现有工作树 → 固化4个反例 → 完整合同识别(F4) → 保存边界重建(F1) → focus范围(F2) → repair预算(F3) → 定向PG/旧路径/合法编辑回归 → 实际Plan的Edge消费 → 31项矩阵补证 → 现有额度内至多1个新真实代表。

同源变体属于本轮范围，连续修复；只有独立新根因、缺少可复用独立权威基准、需要新迁移/API或越过正式操作边界时再STOP。不能再报告“951个测试通过，所以4个反例可以忽略”。
