## 5. 数据与 Seed：先复用，再补缺

### 5.1 对象对应

Goal Blueprint 与 Outcome Profile 优先保存为领域包的版本化内容；Learning Spine 复用来源、章节和阶段分配；Plan Instance 复用学习项目、草案及计划版本；Supplemental/Comparison 优先用资源分配角色表达。Knowledge Module 与既有 KnowledgeNode/LearningUnit 先明确粒度：是同粒度复用，还是多个节点的有名组合；只在确有缺失时增加最小关联，禁止维护两份相互竞争的知识事实源。

Knowledge Exposure 关联模块、阶段/单元和来源章节，并区分计划安排与实际学习记录。稳定键由受控目录或服务端产生；模型只能引用允许的键，不能决定数据库主键、项目归属和发布状态。

### 5.2 Seed 发布

Seed 的编辑来源是受版本控制的文件；运行读取数据库中明确发布的版本。导入先解析和校验，再在事务中发布，不提供任意脚本执行入口。不从用户上传内容中执行命令。

导入校验至少覆盖：Schema、稳定键唯一、引用存在、必需依赖无环、章节真实顺序、模块映射、版本一致、角色合法、来源信息与安全 URL。领域包内容、章节映射与来源版本一起固定。相同键和版本、相同哈希为幂等成功；同版本不同内容拒绝并要求新版本。

首次验收内容以原基线列出的 Agent 三类 Blueprint 为起点：Knowledge/RAG Agent、Coding Agent、Workflow/Automation Agent。[S01] 这不是宣布其他领域被删除：把旧需求已明确承诺的其他领域逐项加入内容验收表。通用引擎支持导入更多领域；未整理内容的自动候选不与已审核 Seed 宣称同等可靠。

不要设一个任意“课程数量”指标来凑数。验收要求是：每个在内容验收范围内的 Blueprint，其必需模块都有合理学习安排、可定位的主要资源或清晰的缺失说明，并具有可执行实践链。不能所有阶段都只给搜索词而声称该领域内容已经完成。

### 5.3 快照与来源可信状态

已确认计划保存所选来源版本、标题、URL、章节区间和映射依据，不在读取历史时替换为公共目录的最新内容。可达性检查可以更新提示，但不能静默改写用户当时确认的结构和来源。

`imported_at`、`link_checked_at` 与内容审核状态分开。创建一个对象不能自动代表网页已核验。只拿到标题/目录时不得声称读完全文。资源内容当作不可信数据，不得提升为系统指令。

跨用户只共享公开、受控 Seed 及公开资源元数据；不共享带用户总结、私有检索结果、个性化目标或 Prompt 的生成缓存。不为本周开发通用向量缓存或复杂淘汰系统。

## 6. 规划执行：少调用，但不丢逻辑

建议正常命中 Seed 的主要生成路径为：目标解析/必要澄清 → 候选包与 Profile 选择 → 代码展开依赖与映射 → 有界资源补全 → 模型组织阶段解释和任务 → 确定性校验 → 草案入库。

正常路径以约 2—3 次主要生成调用作为优化方向，而不是硬性正确性限制；已知目标可更少，缺口或歧义可增加受预算约束的调用。解析、搜索工具调用和结构修复也计入实际用量，不能藏在“主要调用”之外。每次生成最多两次内容修复；SDK、HTTP、Graph 和业务层不能各自重试并放大总次数。

模型输入只包含当前授权范围内的目标、候选 ID、必要摘要、版本与局部上下文。目录查找、依赖闭包、角色检查、章节排序、合法状态、哈希、发布和权限由代码判断。结构化输出只解决格式约束，内容正确性仍需测试及样例审阅。[S09]

澄清未完成时保存普通目标草稿，不创建跨天暂停的付费任务。用户缺时间偏好时可显示可编辑的假设，不强迫多轮问答。计划只给工作量估计范围，不宣称精确学习时长或就业效果。

完整纲要必须先包含所有阶段的目标、核心模块和预期产物。按需展开仅补充细节；若新增必需知识、改变阶段顺序或验收要求，必须形成变更预览并走新版本确认，不能以“延迟生成”为名改写已确认路线。

## 7. 短任务、数据库确认与安全恢复

### 7.1 状态分离的首选落地

新生成任务的计算完成条件是：草案已持久化且可授权读取。此时 `ai_runs.status=succeeded`，`result_ref` 指向草案；草案自身仍待用户确认。计算成功不等于路线发布、更不等于用户学会。

当前代码只允许 `succeeded + next_action=none`，而 `waiting_user + review_draft` 是另一组合法组合。[S04] **首选保留前者：前端在生成完成后按 result_ref 获取草案 DTO，由草案状态显示编辑/确认按钮。** 不直接创造非法的 `succeeded + review_draft` 组合。任何必要的 API 字段变动一次性同步 DTO、OpenAPI、生成客户端、fixtures 和测试。

新路径不再产生为了等待确认而挂起的 Graph。旧 waiting_user 记录先盘点；有有效草案的继续通过业务确认，缺草案或无法恢复的明确标记并提供安全重试，不删除用户数据。兼容处理只覆盖实际存在的历史记录，不另建长期双引擎。

确认请求重新鉴权，校验 expected_version、草案哈希和状态，在现有业务事务中发布版本。批准、取消、并发操作最多一个成功。修改需要模型时创建新任务；不恢复旧图来执行普通批准动作。

LangGraph 可继续用于短时生成及有限修复；已实现部分复用，不为符合“三张图”的形式再造工作流。旧 Checkpoint 数据库和测试不要求立即删除；新增业务确认不依赖它。官方中断恢复会重新从节点开头执行，这也是减少长期暂停路径的设计依据之一。[S08]

### 7.2 真实异步的最小要求

API 在事务中保存输入快照和队列/Run 记录后返回 202；status_url 必须可直接查询，包含当前 API 契约需要的项目路径或参数。不能先同步跑完模型再返回“任务已创建”。

复用 PostgreSQL 持久任务机制，单机默认一个活动 worker、有限并发即可。只维护一份领取/执行状态权威，不为 queue 和 run 各造独立调度器。网络调用不占用长数据库事务；领取、心跳和结果提交各自使用短事务。保留既有 lease、claim token 和幂等能力，不以单 worker 为理由删除竞争保护。

每次任务固定项目范围、输入哈希、Seed 版本、计划基础版本、Prompt/Schema 版本和 attempt ID。最终提交前再次检查项目仍存在、任务未取消、claim token 有效、基础版本符合预期。旧 worker 或旧模型结果只能作带来源的候选/失败记录，不能覆盖用户的新编辑或复活已取消草案。

### 7.3 重试不是重复派发

创建操作的同键同体返回同一任务；同键异体拒绝。自动恢复首先读取已持久化结果，不能仅凭“worker 重启了”重复付费调用。

未派发的工作可安全重新领取；明确安全失败可在总预算内有限重试；已经派发但上游结果未知时进入 `reconciliation_required`，不盲目重新请求。用户可以明确开启新 attempt，并看到可能重复费用提示。没有供应商计费回执时，用量标未知，不推断为零。

内部数据库提交可做到幂等，但不承诺跨网络外部调用“恰好一次”。不为本周建设自动计费对账平台；持久 attempt 记录、可见异常、人工核对入口和显式新尝试足够。

## 8. 联网与 RAG：真接入，少机制

联网正常路径必须有真实服务成功证据。采用一个实际可用的搜索入口，对每个缺口默认至多一次查询、五个候选、三次有限页面读取；这是可调整的执行预算，不是教学质量指标。处理失败显示原因和替代操作，不无限搜索。

已支持来源可以自动读取目录；其它来源允许粘贴目录或用户手动补章节。视频无可靠分章时保存明确章节说明，不编造时间戳。用户提供的资源先成为私有候选，只有受控审核发布才能升级公共 Seed。

服务端抓取须限制协议、目标地址、解析后的 IP、重定向、体积与超时；防止访问 localhost、私网及云元数据端点。页面展示做 HTML 清洗；不执行搜索到的仓库代码。原文说明与复制的正文分开，只保留必要索引、合法引用和出处。[S11]

RAG 只接既有独立服务：服务端传授权 scope，限制检索条数和输入长度，接收带来源的证据。不把本项目的登录凭证随意转交给 RAG，不依赖前端自报 tenant。至少验证真实检索成功、越权拒绝和服务故障降级。RAG 失效不回滚进度；凭证或服务未就绪时 F17 为 BLOCKED，其他能力继续开发。

真实模型/搜索/RAG 的接口能力先做小规模探测。不能假设“OpenAI 兼容接口”自动支持结构化输出、搜索工具或相同错误语义。优先使用已有已授权服务，避免为本周切换供应商或重建基础设施。

## 9. 修改、学习与界面：优先保护用户输入

### 9.1 有限修改操作

自然语言修改先转成受控操作：替换阶段主线、调整深度、增加准备内容、跳过可选任务、重生成未开始阶段、替换实践方向。模型只提出操作参数；代码检查影响范围、依赖和权限；用户先看差异再确认。

全路线重规划保留，但输出新版本。相同稳定身份且目标、内容版本一致的学习记录可关联；不因标题相似自动继承掌握/完成状态。已开始或完成内容变化时展示影响，旧总结、任务修订和成果仍可访问。

### 9.2 低成本但必须有的体验

优先构建“项目/目标入口、计划审阅、学习工作台、实践与 Prompt、成果与历史”几类主要页面；可用页签和侧栏合并，不为每种对象建立一套后台。

总结与 Prompt 编辑采用服务端草稿保存或明确保存按钮加未保存提示；反馈提交前先保存原文。模型响应迟到时绑定原修订，不能覆盖当前编辑。刷新、网络错误、重复点击与 409 冲突有明确反馈。冲突时保留本地编辑内容供复制或重新提交，不默认覆盖另一版本。

学习结束默认简短总结，反馈仅引导；阶段复盘再集中回顾。Outcome 产物从实际任务与记录归集，不要求每次总结都写完整简历材料。无证据时显示“待补充”，不由模型补写不存在的实验结果。

前端至少有空状态、加载/排队、可恢复错误、资源不可用、会话过期和取消状态。轮询使用退避、页面隐藏时减频、终态停止；不伪造精确进度百分比或固定完成时间。视觉目标为一致、清晰和可操作，不建设通用图编辑器或在线 IDE。

## 10. 权限、费用与部署边界

账号继续使用安全散列、登录限流、服务端会话、退出撤销、适当 Cookie 属性与 CSRF/Origin 防护。授权以当前服务端成员关系为准，撤销访问后旧会话不能凭缓存永久访问项目。

开放注册不意味着开放无限模型消费。使用现有供应商与用户已明确授权的额度；本项目需按用户/项目限制活动付费任务和总预算。项目设计默认同一项目最多一个活动生成/重规划任务；其它反馈任务的总并发由全局限制控制。额度检查和预留应避免并发超支。

本文件不授予额外购买、充值、调用未知收费服务或改全局配置的权限。没有明确额度时，先完成不产生费用的实现与测试，把真实验收列为阻塞；将缺失项一次性汇总，不对每个小操作重复问同一问题。

生产 `.env`、密钥、原始用户文本不提交 Git，也不写入公开日志。敏感测试材料使用专门测试账号及可删除样本，不向新服务发送真实个人数据。

部署先复用现有单机环境，不新增 Kubernetes、微服务或额外消息系统。公网发布、数据库破坏性变更、用户数据删除和全局角色修改不因“自动实施”获得默认授权。发布前需完成生产模式配置检查及授权。安全备份、临时库恢复和重新启动演练属于交付；演练不能覆盖现有数据。

## 11. Codex 模型与子代理分工

### 11.1 开发模型路由，与产品运行模型完全分开

以下是开发本项目的路由，不是给学习规划产品增加多模型路由器。产品运行时先保持一个实际可用的 LLMPort provider；不要因为开发使用四档路由，就给产品增加四个 provider 或多 Agent 平台。

官方模型页确认 `gpt-6.1-sol` 支持 `low / medium / high / xhigh / max`；High、XHigh、Max 不是不同型号。[S05] 本地客户端、账号和网关是否实际开放对应档位仍需启动时核查，不沿用旧对话里互相混用的 high/xhigh 名称。

| 职责 | 默认路由 | 关键边界 |
|---|---|---|
| 主协调、任务拆分、风险与接口裁决、证据核查 | `gpt-6.1-sol` + `high` | 临时接替 Dots；不亲自包办所有普通实现 |
| 已批准边界内的业务实现、普通集成和调试 | `gpt-6.1-sol` + `medium` | 可按批准规范新增 API/DTO/增量迁移；关键语义变更再升级 |
| 定位、数据核对、机械改动、确定性测试补充 | `gpt-6-luna` + `max` | 保留此前项目 FAST 约定；FAST 是职责名，不承诺该档最低延迟 |
| 一次性难题分析、关键设计反例、疑难并发复核 | `gpt-6.1-sol` + `xhigh` 或 `max` | 仅在触发条件与授权预算内使用，完成后回到 High |

High 必须主导权限、RLS、事务、幂等、取消/迟到结果、迁移风险、对外副作用和公开契约语义的设计。**这不等于只能由 High 敲代码**：方案、修改范围和验收冻结后，Medium 可实现；关键路径由独立上下文复核并运行真实测试。

默认最多三个活动子代理，最多两个同时写业务代码；共享契约、迁移编号、生成物和同一业务状态对象由单一负责人管理。只读与写入范围明确；不同时改同一文件，不互相撤销未提交内容。工作树/分支仅在实际需要且当前环境支持时使用，不因此重搭开发环境。主协调负责集成。

不强制建三套静态角色配置。派发时同时请求模型与 effort，并记录实际解析值；官方说明未明确设置时可继承父级，且已有 custom agent 文件可覆盖请求配置。[S07] 自然语言声明“用 Luna”不是路由证据。客户端不支持精确派发时如实记录限制，使用当前可用主会话顺序执行，不假装完成多模型调度，不未经授权安装新调度层。

### 11.2 升级与降级

Luna 遇到权限、跨域一致性、架构变更等风险立即交回 High；普通复杂实现转 Medium。确定根因的机械失败可定向修复一次，不无限重复同一路径。

High 先缩小问题、补证据和复现；下面情形才考虑 XHigh/Max：多个合理方案对数据保全有实质冲突；跨队列/数据库/外部调用的因果链仍无法判清；经过两轮有新证据的定向尝试仍无可验证进展；发布前关键不变量存在未解决分歧。两轮是停止无效重试的门槛，不要求高风险问题先浪费两次尝试。

Max 接收一个压缩 Evidence Packet，回答一个具体问题，默认只读。任务不能是“重新阅读全仓库保证全部没问题”。是否使用 Max 取决于当前账号可用性与既有授权；未知额度不静默升级。XHigh 可作中间档，但不是必须逐档试满。

High 作为默认指导档是本项目工程建议，不是本仓库 High/Max 对照实验结论。更高 effort 可能改善复杂工作，也会增加响应时间和 token 使用；实际取舍需用相同证据比较可验证缺陷、返工和通过测试的结果。[S07] 更高档不替代凭证、真实测试、内容校验或用户验收。

### 11.3 交接与记忆

根 AGENTS 只放范围、不变量、路由摘要和文档入口；完整实施约束保存在本文；单一 `progress.md` 记录当前切片、HEAD、已验证项、阻塞与下一步。不另造多层记忆系统。

每个子任务使用：`Goal / Constraints / Allowed Changes / Non-goals / Tests / Evidence / Rollback`。子代理返回 inspected/changed files、实际命令与退出码、测试版本、失败尝试、未确定事项和建议下一步。主协调复用证据，不要求每个代理重新扫全仓库。

## 12. 分层测试与发布门禁

先检查现有脚本与锁定环境再运行，不假设旧报告中的命令仍适用。每个改动跑相关测试，集成点跑契约与回归，发布前跑全量。修改旧规则相关测试时，记录替换理由并添加新的性质测试；禁止靠跳过、删断言或扩大允许范围把真实失败变绿。

### 12.1 四层验证

第一层：纯规则和 Fake 适配器测试。验证依赖闭包、章节顺序、缺口差集、状态、操作解析、输入上限和结构修复次数。

第二层：真实 PostgreSQL。验证受限角色权限、复合归属、事务回滚、重复确认、同键冲突、版本隔离、Seed 发布、任务领取/取消/迟到结果和历史保留。

第三层：真实云模型、搜索、GitHub/RAG 适配。记录提供商/模型、输入摘要或哈希、引用、时间、结果和未知用量。Fake 只能证明接口逻辑，不能代替这一层。

第四层：浏览器真实构建。使用真实后端和 PostgreSQL跑完整流程；至少一条代表性路径使用真实模型及资源，其他大量边界可使用受控替身。浏览器中人工走查主流程与错误页面，不能用 `tsc`、TestClient 或截图存在替代产品可用性。

### 12.2 建议的小型质量样例集

为三个初始 Blueprint 各准备“典型目标”和“约束冲突/资料缺失”两类样例；再补 Exposure 重复、无效资源、局部重规划保留历史、Summary/Prompt 反馈的代表样例。用例数可以复用合并，不为凑数字反复收费。

每个样例提前固定必须满足的性质：目标与交付物匹配、先修完整、范围有界、章节引用可定位、必需缺口有处理、实践可执行、已知不确定性显式。自动检查结构，人或独立评审检查内容；不把模型自评分当最终质量门。

### 12.3 必须验证的危险场景

| 门禁 | 需要证明的性质 |
|---|---|
| Q01 | 账号 A 不能读取/修改账号 B 的项目、Run、草案、总结、成果或 RAG 私有证据 |
| Q02 | 生成入库后断开浏览器，重新打开可继续；未入库不得给出已成功提交提示 |
| Q03 | 同一个确认被重复提交，只产生同一正式结果；同键异体报冲突 |
| Q04 | 取消与发布竞争、旧 worker 迟到、用户修改期间生成结束，都不造成覆盖或复活 |
| Q05 | worker 分别在调用前、调用结果未知、结果落库后退出，恢复不盲目重复付费 |
| Q06 | Seed 更新后历史计划内容稳定；同版本不同内容导入失败且不半发布 |
| Q07 | 局部/全路线新版本不删除原总结、任务修订和成果；Exposure 不错误全局完成 |
| Q08 | 搜索超时、资源失效、RAG 不可用都有明确降级，不伪造 URL、时间戳或引用 |
| Q09 | 模型返回合法 JSON 但非法模块/章节/项目引用时，发布被阻断或按明确规则降级 |
| Q10 | Summary/Prompt 超时或 409 时用户原文不丢；导出绑定正确修订 |
| Q11 | 状态轮询地址实际可查询，终态不继续无休止轮询；错误视图可操作 |
| Q12 | 构建、启动、重登录、备份并恢复到独立临时环境后，代表数据仍可读 |

发布条件：F01—F18 全部有对应实证，无未解决的安全/数据保全/核心链路阻塞；Q01—Q12 通过；用户实际体验的待确认项明确完成。任何真实服务未接通只能登记 BLOCKED，不以降级体验伪装该功能验收。

低影响外观问题可登记后交付，但必须列具体影响；不能用总测试数或百分比掩盖某条关键能力缺失。

## 13. 七天排布与垂直切片

日序表示冲刺排布，不是假设本机当前时间或承诺完工日期。中途继续时按真实进度，不机械重跑“第一天”。

| G0 | 第 1 天起始 | 一次差异审计、规则替代清单、功能矩阵、实际路由/凭证能力记录；立刻进入 G1，不能把文档整理当本轮终点 |

| G3 | 第 4 天 | 总结反馈、主项目、阶段任务、用户方案、Prompt 修订和指定版本导出 |

前端、后端、Seed/样例可以并行，但同一契约只由一人整合。每个切片都有可见用户结果；禁止连续多轮只改框架、目录或抽象接口。
