先确认实际工作目录与 origin、本机 HEAD、dirty files、现有服务与占用、锁文件和迁移 head；对照指导文档列出已经存在和真正缺失的能力。不要从头扫描无关仓库，不因远端报告过时重复开发。审查参考是远端 `a9c469e`，本机真实状态优先决定改动起点。

将指导文档保存到 `docs/implementation/CODEX_GUIDANCE_V2.0.md`；保留当前 Goal 到项目文档；在现有 AGENTS 中增加短入口、不变量和路由摘要。创建或复用 feature-acceptance 和 progress 文档，按现有编号规则新增一份替代 ADR。文档够指导实施即可，不开展多轮文档重构。

读取已有授权和配置的必要信息，只记录凭证是否存在及能力，不回显 secret。统一列出真实模型、搜索、RAG、付费预算、部署权限等实际阻塞；已有信息能解决的不要再问。

### G1：第一个真实用户纵向切片

在当前会话立即实现或补齐：注册/登录 → 首份可导入的真实 Seed → 用户目标 → 请求持久化并返回任务 → 真实模型生成 → 浏览器查看/修改草案 → 业务事务确认 → PostgreSQL 正式版本 → 刷新和重新登录回读。

Seed 内容和界面可以与后端并行，使用明确的文件归属与已批准契约。默认不超过三个活动子代理，最多两个同时写业务代码；同一迁移、生成契约和共享状态对象由单一负责人整合。

完整生成链暂被收费授权或外部凭证阻塞时，继续实现相关接口、测试、页面及其他独立模块，但为真实服务测试明确保留 BLOCKED，不能以 Fake 替代完成标准。

G1 满足相关验证门禁后，不重复请求已获得的实施授权，继续按指导文档完成资源/Exposure/偏好/联网及 RAG、总结/实践/Prompt、重规划/成果/Outcome、全量验收与授权环境交付。

## Tests 与 Evidence

按照指导文档第 12 节执行四层验证和 Q01—Q12，使用本机核查后适用的实际命令。必须区分 Fake、真实 PostgreSQL、真实外部服务和浏览器验证；报告精确到对应提交、环境、命令、退出码、证据路径和 NOT RUN/BLOCKED。

对每项 F 功能记录 `NOT_STARTED / IMPLEMENTED / VERIFIED / BLOCKED`。涉及真实能力时只有静态检查不能进入 VERIFIED。至少检查真实异步返回、重复确认、越权、取消竞争、迟到结果、未知付费结果、公共 Seed 更新不污染历史、重规划保留原文、模型失败时用户编辑不丢失。

内容验收使用预先定义的代表样例和性质，不以 JSON 合法、模型自评分或测试总数量替代教学与产品质量。最终用户体验确认是单独证据，不冒用用户身份批准。

## Rollback 与中断恢复

复用当前可安全工作的分支/工作树策略。提交只包含本轮拥有的修改，不捎带他人未提交内容。回滚优先代码级可逆变更；数据库按增量迁移与备份策略处理，不能默认 downgrade 就安全。

遇到权限不足、破坏性操作、真实数据冲突或未知费用，只暂停受影响分支，报告具体风险和最小授权需求，继续其它独立工作。

会话或上下文结束前保存检查点：实际 HEAD、已验证功能、未提交文件归属、仍在使用的服务、未运行测试、阻塞、下一条安全动作。不要承诺当前工具不支持的后台继续。续接时读取检查点，不重新开始全仓库审计。
