# 路线与单元编排示例

本文件是实施后的期望，不是 Agent6 当前冻结 JSON，也不是新课程正文深审。章节来源沿用现有研究包与远端 BINDINGS；实施时以最新受控资料的实际范围与资格核对，不能用本文件提升证据等级。

## 1. 默认完整 Agent 公共段

| 学习段 | 主要资料范围（沿现有池） | 应出现的学习成果 | 后面如何继续，不重复什么 |
|---|---|---|---|
| A0 模型与程序职责 | Hello ch1 1.1/1.2/1.4；ch3应用基础；Python函数/JSON/异常按诊断补 | 能解释一次模型响应和程序执行的区别 | 不把长历史或训练数学放成硬前置 |
| A1 Agent Loop | Hello ch4 4.1–4.4；LCC s01/s02作对照 | 正常两步调用、坏工具/坏参数、轮数上限；开始Eval-Lite | Coding后续只对照调用协议差异 |
| A2 组件与受控执行 | Hello ch7 7.1–7.5；LCC s03 Permission、s04 Hooks | 职责、注册、权限、错误、审计可分若干LearningUnit | 不要求产生多个新canonical key |
| A3 知识与Memory基础 | Hello ch8 Memory/RAG/问答；All-in-RAG ch1最小链 | 看见检索结果与来源，知道无证据出口 | RAG专项不再从头定义RAG |
| A4 Context | Hello ch9原则/ContextBuilder/NoteTool/TerminalTool；LCC s08/s09对照 | 大结果处理、约束保留、重读与持久记忆区别 | Coding/RAG后续只深化具体上下文问题 |
| A5 Framework一深多浅 | Hello ch6.1/目标框架；已有LangGraph Workflows/GraphAPI，以及最小Persistence/Interrupt受审范围 | 用一个框架接入既有工具，展示state/branch及一个失败或暂停恢复例子；比较其他框架 | Workflow再学跨进程重放、幂等、多会话，不完整重复此例 |
| A6 MCP | Hello ch10.1/10.2/10.5；LCC s14只作mock比较 | 真实协议心智模型、复用只读server、最小server和错误/权限边界 | 不把mock工具池当协议运行；高级远程认证目标才展开 |
| A7 系统评价入门 | Hello ch12.1–12.4；现有evaluation-types | 利用前面实践的任务与失败记录构造测试集，区分结果判据与模型自述 | 后面按专项追加指标；不是此时才第一次测试 |
| 小型开源核心学习（A8后继） | 沿Agent6已绑定Pi受审文档及可替换候选；具体源码由外部AI当时读取 | 核心地图、一条正常/失败链、与教程比较、一项验证与迁移建议 | 不是全仓所有插件/API，也不是完成全部专项 |

自己的项目贯穿全部行，不额外插一个必须从零创建的毕业Demo。MCP与Framework是完整路线的默认能力，不表示每个项目都必须将两种技术强行装进运行链。

A5认真学习的程度以“可以实际用它组织一个有状态、有分支、有明确失败边界的小应用”检验；只看框架介绍或五个README不算一深。其他框架的比较只需得出适用条件，不要求各实现一次。

## 2. A2 多单元：合法细分与非法扩张

下列key名称是解释性占位，不是新增公共节点声明。

```json
{
  "units": [
    {
      "title": "模型负责决定，工具负责执行",
      "node_keys": ["<当前冻结的A2知识key>"],
      "focus_refs": ["<已审职责分离范围>"],
      "objectives": ["对比同一输入的模型返回、工具分发与实际执行结果"]
    },
    {
      "title": "权限拒绝以后，动作为什么不能继续",
      "node_keys": ["<同一个A2知识key>"],
      "focus_refs": ["<已审权限与审批范围>"],
      "objectives": ["利用已有练习的拒绝案例解释执行边界"]
    },
    {
      "title": "错误、超时与执行证据",
      "node_keys": ["<同一个A2知识key>"],
      "focus_refs": ["<已审错误与审计范围>"],
      "objectives": ["区分工具失败、未执行和已完成，并指出支持结论的记录"]
    }
  ]
}
```

服务端为这些unit分配／验证稳定身份；从冻结目录恢复A2的canonical节点及A1→A2等真实依赖；现有实践任务与acceptance不随unit数量增加。

不能这样处理 v6.10 失败响应：把六个新node的字段名改成unit就全数接纳。先比对受审scope。若其中有范围外概念，则保留待审建议或拒绝；本轮不凭空判断那六项。

也不能将所有教学细节折叠成空泛的一个unit求稳定。代表A2必须演示一个canonical对应多个可见、各有具体学习目的的unit；其他阶段不强制恰好三个unit。

## 3. 完整 RAG 目标：一条明确可见的后半路线

入场：公共段和小型核心源码已建立整体心智模型。已有等价知识者做检查后进入对应段。

| 阶段 | 现有来源范围 | 和前面怎样衔接 | 实践/输出 |
|---|---|---|---|
| G0入场复习（可合并为下一阶段开头） | All-in-RAG ch1；Hello 8.3–8.4对照 | RAG定义REVIEW，从“知道位置”到系统管线 | 画写入/查询路径，标坏例发生位置 |
| G1数据入库与切块 | All-in-RAG ch2/04、ch2/05、ch8/02 | 新增来源定位、切块影响 | 同一语料对比块边界，能回到source/section |
| G2Embedding与索引 | ch3/06、ch3/08 | 表示与检索分离 | 建最小索引，说明模型/维度变化的影响 |
| G3基线与评估 | ch4/11、ch6/18；受审RAG评估指标 | 在混合前有单路基线 | 标注小集合，分别观察检索与回答错误 |
| G4混合与查询处理（目标需要） | ch4/11、12、14；ch8/03；BGE-M3比较 | DEEPEN，不把learned sparse等同BM25 | 对照基线，记录融合后改善和退化 |
| G5重排、上下文、引用 | ch4/15、ch5/16、ch8/04；citation范围 | 已召回不等于能支撑回答 | 定位排序/预算/引用支持性问题 |
| G6集成回归 | ch6/19（按需）、ch8已学段综合 | 不再次完整重学所有章节 | 固定坏例，比较一次改变前后结果 |
| 成熟RAG工程切片 | RAGFlow/WeKnora或其他合适候选；已有项目卡 | 现在才研究选定的入库/检索/证据子系统 | 当前实现地图、失败链、与G1–G6的比较；不全仓遍历 |
| 迁移与验证 | 用户自己的持续项目与现有测试 | 选择1–2项适用机制 | 最小改动建议、验证证据与不迁移理由 |

GraphRAG/Agentic RAG只在需求与前置满足时展开G7，不成为查看普通成熟RAG检索实现的硬前置。

最后两行可以按选定工程问题拆成多个清晰阶段；不能塞回G6的普通资料区，或只写“以后研究RAGFlow”。

## 4. Coding：Pi不是被放在最后的附赠链接

默认路径：公共核心中已经用LCC基础段作对照 → 必要TypeScript/异步阅读补缺 → Pi核心整体学习 → 选定Coding教程深化 → 需要时进入大型隔离/多工作区工程切片。

Pi初次只覆盖足以理解工具/会话主链的边界；不为了提前看Pi而把全部Session/Extensions/并发机制都当已会。后面再读同仓深层Session或取消时明确DEEPEN。

深化按现有C组：C1 loop REVIEW；C2文件/shell与权限边界；C3计划状态；C4代码上下文与压缩；C5项目记忆与任务；C6长任务/取消。协作C7、协议集成C8、运行完成判断C9按目标；已在A6学过MCP时，C8聚焦Coding中的适配差异。

OpenHands等只在隔离执行、服务化或多workspace目标出现时作为成熟候选。其部分资料原审读仅目录级，不能因重新安排就升级为已审Primary。项目学习Prompt可以安排当前源码核查，但必须如实说明该范围尚未由平台执行或逐页深审。

不要强迫用户同时“另做一个Coding Demo、完整学Pi、完整学browser-use、再完整学OpenHands”。

## 5. Browser：必要前置可以在小项目之前

推荐路径：

公共核心 → 必要Playwright B0/B1/B2范围（页面、定位、最小等待、异步入场）→ browser-use核心学习 → 按目标深化动态内容/重试B3、会话与权限B5、任务评估B6 → 需要的成熟复杂子系统切片与迁移。

B4 quickstart与核心源码学习可在相邻单元衔接，区分“使用库完成例子”和“追踪源码解释原因”。既有B7不要整段未经裁剪搬到前面，否则又把进阶前置遗漏；生成新范围后继并保留旧版本。

browser-use核心不是全库所有语言、Cloud、CLI、部署体系。它可以就是本路线唯一参考仓库；后续确有更复杂问题时再研究其对应子系统或另一个候选，不为了凑“大项目阶段”虚构第二个仓库。

练习使用自控页面与受许可动作，MFA/凭据/支付/真实发布不由默认学习任务触发。缺浏览器基础时不能因为“它是小项目”跳过入场教程。

## 6. Workflow：A5已经会的不要重学

公共核心A5已实践一个主框架 → 小型Agent/Workflow核心项目（可用同一个参考的适当范围）→ W0/W1按已有程度REVIEW/COMPARE → W2错误分类 → W3checkpoint/store/thread与重放 → W4人工审批及幂等副作用 → W5回归 → 所需成熟runtime恢复切片。

W6后台/多会话/服务、W7多Agent只按目标追加。若A5已完成最小checkpoint/interrupt，专项说明本次新增的是跨进程、重放、失败和副作用边界，不能再从安装框架起完整做一遍。

不要把LangGraph官方教程的hello-world自动认定为已经完成成熟小型开源项目的整体拆解；资源作为教程还是源码案例应有不同学习任务。

## 7. 组合目标与尚未选专项

旅行Agent示例：用户主目标是可恢复规划，Browser用于读取信息，RAG用于已有资料。可把Workflow作为主要深度，Browser/RAG选必要能力，不强制三个完整专项和三个大项目。用户明确希望三者都深入时才进一步展开。

未知Voice目标：公共主线与可复用工具/上下文能力仍可规划；voice专项缺资料时明确待审，不伪造课程和仓库；不能把它强制归入RAG。

“先做最小应用”的阶段目标与“系统学习”的总体目标同时保留。界面清楚标识本次完成到哪、哪些后续待用户选择，不因“最小”删掉整个长期学习地图。

## 8. AI全栈与云服务的迁移原则

| 方向 | 小型源码之前 | 小型源码学习 | 专项深化 | 成熟工程阶段 |
|---|---|---|---|---|
| AI全栈 | 对应Web/JS/React/API/必要数据与GenAI应用教程；不是所有人重修全部语言 | 已审且适合当前技术栈的真实AI Web核心 | Streaming、持久化、Auth、结构化输出等按目标逐段 | 大型AI产品选定数据/会话/可靠性等切片 |
| Cloud | 有服务直接复用；没有才补最小service；Docker/Compose与必要网络 | 规模可控的多组件服务或已有服务部署链 | 手工云部署后CI/CD、可观测/恢复；IaC/K8s按目标 | 对应平台/云原生系统的所需切片 |

这两方向不强加Agent的A5/A6，不改变各自合理教学顺序。Node已有服务不变成Python任务；云商/数据库未选时明确哪些本地练习可做、哪些生产操作待选。
