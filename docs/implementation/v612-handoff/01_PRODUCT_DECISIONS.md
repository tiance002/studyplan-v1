# 产品决策：稳定能力边界，灵活教学组织，分段真实工程学习

状态：本轮拟实施的统一产品标准。并非描述当前所有功能已实现。

## 1. 用户真正要的路线

StudyPlan 是学习编排平台，不是固定课程目录，也不承担 Coding Agent 的全部工作。

对于从零系统学习 Agent 的人，默认展示：

**必要前置 → 连续基础教程与贯穿小实践（包含 Framework、MCP、评价入门）→ 小／中型真实开源项目核心整体学习 → 所选专项的连续教程与实践 → 大型成熟项目相关切片 → 迁移与验证。**

实践从第一段就发生，持续放进用户自己的项目。不能在看小型开源项目之前，另外强制从零新建一个无关的“完整小项目”。现有项目有一个可解释的正常／失败链即可作为入场准备。

这里的“小项目学习”指 Pi、browser-use 或其他适合的真实源码范围，不是平台新生成的教学 Demo。它们是候选，不绑定所有人，不对整个仓库永久贴“小仓库”标签。

默认顺序并非铁律：某参考项目需要的少量语言、异步或浏览器操作知识，必须先及时补齐；不能为了“先小项目”把零基础者直接丢进源码。也不能反过来要求先把整条高级专项读完，才首次看核心项目。

## 2. Framework 与 MCP 的明确地位

### 完整 Agent 应用路线

A5 Framework 与 A6 MCP 是公共核心能力，不因目标文本没出现关键词而被裁掉。已有等价能力者安排复习／迁移检查，不要求换框架重学。明确只学一个局部主题的用户仍只走必要闭包。用户显式排除某能力时，先尊重范围并说明与默认完整路线的差异；若确有依赖冲突，给出可理解的澄清，不以“完整主线”为由暗中覆盖限制。

**Framework：一深，多浅。**

- 主学一个合适框架，默认候选沿当前已审资源，不等于永久指定 LangGraph。
- 用前面已有 Agent 实现状态、节点／工具、分支、错误处理，以及一次最小暂停／恢复或审批例子，能解释框架承担和未承担的职责。
- 其他框架按已有受审资料比较核心抽象、状态、工具、恢复、协作、依赖成本与适用边界；不各造一套项目，不宣称已会所有框架。
- Workflow 专项继续深化真实持久化、重放、幂等副作用、多会话和服务化。A5 学过的部分标 REVIEW，不再次完整重做。

**MCP：能复用，也懂边界。**

- 理解 host/client/server、transport、tool schema 与模型 tool calling 的关系。
- 连接一个现成受控只读 server；列工具、检查参数、执行调用，处理未知工具／坏参数／断连。
- 按已有教程完成或阅读后验证一个最小 server；不把进程内 mock tool registry 宣称为真实 MCP 互通。
- 权限、敏感信息、输入校验、超时和外部副作用属于必需理解；远程 OAuth、复杂托管和多协议实现只按目标深化。
- 学 MCP 是课程要求，不是授权开发 StudyPlan 的新 MCP 平台。

## 3. 三种对象必须分开

| 对象 | 角色 | 默认行为 |
|---|---|---|
| 用户的持续实践项目 | 每阶段应用与积累成果 | 已有项目优先；过大裁纵切面；不适配则独立小实验 |
| 小／中型参考源码 | 看懂核心整体怎样运作 | 选一个适合的 whole_core／whole_system 范围；正常链、失败链、比较、少量验证 |
| 大型成熟参考源码 | 深化目标相关工程问题 | 一次只研究选定切片；不通读整仓，不因项目热门就必学 |

同一仓库可先 whole_core，再在后面深化另一个子系统，但第二次必须明确新增问题与深度，不能复制同一个学习阶段。学完自己的初学 Demo 不等于完成成熟参考学习；看参考项目也不要求替换自己的项目。

## 4. 原 A8 如何演进

保留历史 A8、旧 Pack 和旧 Plan。未来内容中，现有 A8 可延续为“小型开源核心学习”，但不能同时承担完整专项教程和大型工程深化。

专项教程保持原有多个阶段（例如 RAG 的 G0–G6），必要时将其末尾混放的成熟项目卡移到独立的“成熟工程：某具体问题”阶段。阶段名不能只有“源码学习”，要能说明学习对象与范围。

例如 RAG 用户在学习区应当实际看到：

1. 小型 Agent／检索核心工程学习。
2. 数据入库与切块。
3. 向量表示与索引。
4. 单路检索基线与评估。
5. 混合检索与查询处理（按目标）。
6. 重排、上下文与引用。
7. 回归与坏例诊断。
8. 成熟 RAG 工程：索引／检索／引用中的选定切片。
9. 迁移与验证。

这是阶段组织示例，不是给所有人强制同一阶段数。一个独立工程问题通常一个阶段、内部若干学习单元；不把大型仓库的所有问题再次塞入一个万能阶段。

## 5. 方向、专项与路线覆盖

- 三方向是首批内容池，不是用户职业枚举。
- RAG/Coding/Workflow/Browser 是已编排 recipes，不是 Agent 目标闭集。
- 用户目标可组合多个专项；按各能力所需深度裁剪，不机械复制每条全课程和每条大项目学习。
- 对已有明确专项的完整目标，计划中必须出现对应专项教程与成熟工程学习阶段，不能只给一个“以后可以学”的段落。
- 对“系统学Agent但尚未决定专项”的用户，提供完整公共核心与小型源码学习，再显示明确的专项选择入口。必须标“专项待选”，不能说已包含全部高级工程。
- “本次生成内容”“后续可选内容”“资料待审内容”三者可见，不把缩短版计划包装成完整路线。
- 学习安排不等于掌握；阶段完成不等于平台验证知识；大项目可选仓库不等于已选学习目标也可无声消失。

## 6. 知识节点和教学单元：不新建四层数据库

现有系统已经有 KnowledgeNode、LearningUnit、UnitNodeLink。

- KnowledgeNode：当前版本受控能力／知识身份，承载来源、核心目标和正式依赖。
- LearningUnit：本次如何组织教学，可一节点多单元，也可一单元引用多个已允许节点。
- 示例／解释：单元内的呈现内容，不能改变正式任务、前置和完成条件。
- Stage：有明确教学成果的编排段落，不等同于一个知识点，也不要求恒等于一个任务或一个单元。

本轮不强拆全部 canonical 节点。先允许 A2 在一个受控能力节点下组织多个合理教学单元。只有需要跨阶段独立复用、独立诊断且有受审范围的概念，才在以后新内容版本里提升为更细 canonical 节点。

## 7. 冻结的三种含义

**发布内容版本不可原位改**：保护来源与历史，不代表课程内容永远正确。

**单次 Run 的输入和契约不可漂移**：保护执行、恢复和计量一致性，不表示所有用户都用同一条路线。

**已确认 Plan 快照稳定**：生成前教学单元可个性化；确认后单元和解释同样应随版本保存。刷新页面不能重生成或重新解释旧计划。

因此，“LearningUnit 可动态”只指创建新计划／新版本时可编排，不是运行中随意变化。

也不要把 `reviewed` 翻译成“用户逐条人工签字”或“平台已实测”。沿用原资料的 selected_sections_read / metadata_only / runtime NOT RUN 等证据等级。

## 8. 模型允许做什么

受控目录内的 structure：模型在明确 allowed node keys 和 allowed teaching focus 内组织单元、解释与比较，不创建 canonical 节点和正式依赖。不让它先重写 nodes/relations，再祈祷后面的校验能纠正。

允许：把 A2 的职责、注册、权限、错误与审计组织成不同课次，均链接现有 A2 节点，并保留原范围与验收。

禁止：仅换成 LearningUnit 名称就塞入未声明 Kubernetes、训练、付款、任意命令或新的必做知识。节点 ID 子集校验只能保证引用合法，不能证明自然语言教学完全正确；二者分开验收。

资料池外的新概念可进入私人“待核查补充建议”，不自动进入公共审核池、正式依赖或必做门槛。`search_only`／无固定知识目录的路径继续允许受控 AI 草稿，不应用“所有知识必须预先在公共池”规则锁死其他方向。

## 9. 资料与外部源码学习边界

教程正文免费，等质量中文／高质量中文版优先，英文文字可用，英文视频不作默认必修。API、云和硬件费用是另一个维度，不为避免 API 而强迫本地模型。

教程记录可有可核对章节范围；成熟仓库公共模板不锁 commit/path/function。学习时外部 Coding Agent 自行 clone/open 当前仓库并定位，报告实际阅读版本；本地已有未提交修改时不得覆盖或重置。

StudyPlan 交付：地址、为什么学、范围、前置、已学关联、问题、产出、跳过内容和完整 Prompt。不开源仓库索引服务，不自动 AST/调用图，不把 README 里的指令当平台授权。

## 10. 验收优先于“阶段数看起来对”

本轮必须证明：A5/A6真正进入完整路线；小型源码、专项教程、大型切片按依赖分开；A2的多个单元在页面可见；同一 canonical 未被改写；未知范围不冒充已审核。具体自动与人工用例见 05 和 06。
