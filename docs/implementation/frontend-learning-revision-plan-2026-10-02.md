# 学习工作台改版：实施边界与审阅决定

日期：2026-10-02。依据：用户已认可浅蓝 HTML 审阅稿并要求修改正式前端；随后明确取消额外退出条件/4-of-5 通关，改用阶段总结和现有实践环节。

同日后续明确修改：资料三项操作各自按钮+浮窗，移除手动进度表单及知识节点状态；统一自动二态阶段进度。对应 [ADR-0013](../adr/ADR-0013-automatic-stage-progress-and-resource-dialogs.md)，本轮继续实施，不恢复旧单元状态界面。

## Goal

在现有 React 工作台实现浅色视觉、阶段内折叠节点、同步学习位置和真正按阶段保存的总结；课程建议加入贯穿 Eval-Lite、Eval/Reward、RL 基础与可选训练、进阶评估，并表达按目标选择的能力依赖。

## Constraints / Non-goals

- 复用 ongoing V2 分支 `feat/v2-g1-user-slice`（从 develop 起点延续）；不提交 master、不接受里程碑、不合并未完成的完整产品 Goal。
- 不操作 `.workbuddy/`、`design-preview/`；不改历史 Seed、已确认路线、原文、成果或历史迁移。
- 不引入新 UI 框架/依赖、训练框架或图编辑器；不调用付费模型，不自动生成/批准路线。
- 阶段完成、Exposure 和知识核验保持分离；展示自动完成阶段数而非伪造掌握数，内部旧进度数据不重写。
- 不新增阶段通关门槛；实践保留已有任务验收。阶段总结可以稍后补写，无每日频率要求。

## Allowed changes / ownership

1. Frontend worker：既有组件、样式、位置同步、总结/实践编辑缓冲、课程建议展示与前端行为测试。
2. Stage-summary worker：总结领域/API/仓储、0023 增量迁移和隔离 PG 测试；unit_id=null/省略表示阶段总结，旧明确 unit_id 路径保留。
3. Root：公开契约/生成类型整合、内容来源核对、浏览器验证与报告。最多两个同时写业务的代理。课程建议作为独立前端视图；本轮不发布新版 Seed、不自动改变用户已有计划。

## Tests / evidence / rollback

行为测试先观察 FAIL 再实施；外观通过真实浏览器验证。复用 npm test、tsc/Vite build、pytest 定向及相关回归、Ruff 和 diff 检查。真实 provider NOT RUN。证据写本轮 acceptance，当前 progress 只追加最新检查点。

回滚以普通逆向提交为主。0023 downgrade 必须拒绝已有阶段总结，不删除新历史；旧单元总结与原调用契约保留。公共 Seed 新版本不自动改变已确认私人路线。
