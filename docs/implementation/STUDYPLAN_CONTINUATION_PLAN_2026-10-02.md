## 1. 结论与实施重点

当前不应重做 G1、重搭框架或继续主要围绕外观迭代。推荐顺序是：

**资料候选证据与排序 → GitHub 教程检查及私人接入 → 正式受控 Seed / 三 Blueprint → 项目、目标与 Outcome Profile → 全路线重规划 → 运行恢复与完整交付。**

目标继续覆盖 F01–F18、Q01–Q12及用户实际验收；只减少内部机制复杂度，不删用户能力。整体维持 NOT_READY，直至全部适用门禁及实际接受条件满足。[S01][S03][S04]

### 1.2 本次代码核查得到的优先修复点

`TavilyResourceIndex.find()` 未保留结果摘要及相关性分数，产生的候选均为 TEXT、und、SEARCH_CANDIDATE、UNVERIFIED。`LearningResourceService.search()` 随后调用 `rank_resources()`；在这些字段相同时，当前排序键最终按标题排序。因此，**当前路径通常丢失了搜索返回顺序，而不是正在按教学相关性排序**。这是源码推导，不是本次真实搜索实验的结论。[S05][S06][S07]

增加 GitHub 搜索后不能直接沿用上述语义。与此同时，现有预约后派发、同键回读、私人选取和来源快照值得复用，而不是重写。[S07]

`safe_candidate_url()` 明确只校验展示 URL、不发起候选抓取；它不能单独充当新增 README/章节下载器的完整安全边界。源码里对象创建时间也不能当作内容核验时间使用。[S05][S06]

本计划**明确覆盖**旧文档中冲突的开发模型分工和“现在从旧基线重新执行 G0/G1”的续接动作；不覆盖历史原文，不重写原指导和 Goal 的受保护内容。新增一个短入口指向本计划与新 Goal，保持 `progress.md` 为唯一当前进度。

### 2.1 不得退回旧要求

新注册密码维持6–12个Unicode码点，旧账号登录维持1–128兼容，不重写旧散列。当前浅色UI、阶段/知识父子折叠、学习路径与任务导航，以及三个独立资料浮窗继续保留。[S01][S02]

总结是**阶段总结**，可稍后补写，不恢复每日总结、退出条件、4/5通关或强制AI反馈。阶段只展示 completed / incomplete；由同一 project / plan / stage 的非空已保存阶段总结，加上该阶段全部给定实践对应的既有 USER accepted 成果决定；没有实践时只要求总结。Prompt保存、阅读、自述、模型意见和旧路线 accepted 均不能自动完成新阶段。旧 Exposure/UnitProgress/知识核验数据内部保留，不恢复相关面向学习者的手动进度控件。[S10][S11]

不削弱服务端身份、RLS、复合归属、CAS、幂等、原子发布、lease/claim fencing、取消/迟到结果防护及不可变历史。计算保存草案后结束，用户确认继续走普通业务事务，不恢复旧 Graph 执行批准。[S02][S03]

### 2.3 分支策略：防止从旧 develop 丢掉现有实现

先验证固定提交是本机当前工作成果的祖先，或精确核对差异；存在更新时保留更新，不硬退回固定提交。不要从较旧 master/develop 重建当前实现，也不要为满足“每Goal从develop开始”而先把未经切片验收的整条工作分支强行集成。

## 4. 第一批：N0 → N1a → N1b

### N0：一次有界续接核查

**Goal**：承接现状并立即进入资料链实现，不重新制作整套规划。

**Constraints**：只读检查起点；不重启其它服务、不迁移正常库、不消费队列、不读取或打印秘密；保留他人未提交内容。

**Allowed changes**：新续接计划/Goal入口、必要新ADR、`AGENTS.md`短入口、`progress.md`及功能矩阵最新补充；不改旧指导/Goal原文。

**Non-goals**：不重新实现注册、G1短生成、旧Exposure UI；不启动无界Worker，不全仓目录重构。

**Tests**：记录路径/origin/HEAD/dirty files/分支关系/迁移head/现有服务归属，核对相关测试入口、实际可用模型和账本计数。只读取与切片相关的配置存在性，不打印值。

**Evidence**：一个共享 Evidence Packet，至少有固定点与当前差异、写入归属、模型实测选择能力、待补契约、授权余额及第一条安全动作。后续代理复用，不重复全仓侦察。

**Rollback**：文档可逆提交；没有业务数据改动。遇到未知本地差异先隔离文件，不覆盖。

### N1a：资源证据、排序与安全读取契约

**Goal**：保留搜索相关性，并让“见到名字”“读过README”“检查过章节”“受控内容审核”能明确区分。

**Allowed changes / 模块**：

- 已存在的 `backend/app/domain/resources/models.py`、`backend/app/ports/resource_index.py`、`backend/app/application/learning_resources.py`。
- 已存在的 `backend/app/infrastructure/resources/tavily.py`，相关资源持久化、API、组合根、前端资源DTO与测试。
- 新增 GitHub 薄适配/有限读取模块；必要的增量迁移；`contracts/`及生成客户端同步。
- 下列字段和文件名是设计建议，不是声称当前已有；由契约负责人映射到真实仓库结构。

**最小数据契约**：

| 对象 | 建议字段/语义 |
|---|---|
| 查询意图 | `source=web/github`、当前project/plan/stage/unit、允许的node_keys、查询文本/语言、显式偏好版本（如使用）、幂等键 |
| 首次执行快照 | 首次预约时冻结的实际偏好、目标/阶段语义、计划版本、查询规范化结果、provider与预算 |

| 计量 | 搜索请求、内容文件读取、必要元数据读取分别记录；每次外发都有预约/回执/结果状态 |

在现有私有记录中增加有Schema校验、可版本化的结构字段或JSONB即可；需要跨记录约束时才加关联表。不要将所有语义塞进 `source_note`，也不为每个教学信号新建一张表。旧记录缺字段默认 unknown / metadata_only，不批量补成已核验。公共Seed与私有个性化结果仍不混库共享。

**幂等细节**：外发前完成预约。意图哈希至少包含来源、目标位置、查询和用户显式参数；同键异体拒绝。首次有效偏好与服务端推导上下文存为快照；同键重试读取已存快照，不以“此刻偏好已变化”重派旧请求或替换其结果。回读仍重新校验当前身份/项目归属。缓存命中不记新外发。

**排序规则**：先识别无关、不可用或明显不适合作为主线的候选；再按目标/阶段覆盖、实际教学结构、先修与难度、语言/媒体/技术适配及原始相关性排列。官方身份与教学性分开；官方教程可以主线，纯API参考优先作Reference。Star仅辅助，不用标题字母序覆盖相关性。GitHub没有可用相关性分值时保留返回rank，不制造score，也不直接比较不同引擎未经校准的分数。

采用可解释的离散规则与理由，不首批引入付费LLM课程评分器。信号必须指向实际读取证据；缺证据写 unknown，不按名称 learn/tutorial 判定已通过。

**安全边界**：首批仅用固定 `api.github.com` REST端点构造请求；不任意跟随README链接下载，不自动clone/install/run，不取子模块或仓库外重定向。优先README及少量文本章节，Notebook等未支持格式只给明确链接与未检查提示。外部链接只展示，不自动加载图片/HTML。展示转义或使用既有安全渲染器。[W02][W05]

固定主机白名单不是取消安全校验：仍需HTTPS、准确主机/端口与路径参数、无嵌入凭据、TLS验证、合理DNS/网络出口限制、禁止私网/回环/元数据地址、限制重定向、总体deadline、解压后体积和编码。不得仅靠字符串前缀或先DNS检查后不受控重解析宣称SSRF已解决。后续通用网页读取另以同样边界实现，第一批不建设通用爬虫。

**建议执行上限（项目默认，不是行业标准）**：每个缺口/发现操作最多1次搜索、最多5候选、最多3个内容文件读取；必要元数据读取也有有限单独预算，首次实现可限制为最多2次。一个操作的总网络deadline建议不超过15秒，文件解码后上限建议256KiB；读取失败/截断如实返回，不自动扩页。版本无法完全解析时记录已知blob/hash并说明范围，不将blob SHA冒充整仓commit。

**Tests**：保留provider顺序；相关教程胜过无关agent命名库；纯安装库/官方参考不被自动授予主线资格；旧DTO兼容；同键同体回读/异体409/偏好变化；额度竞争和0额度；跨项目查询/候选拒绝；无结果、403/429、超时、超大/压缩体、私网/重定向/XSS/提示注入数据；公共快照不含私有目标/总结。

**Evidence**：规则/Contract/Fake、真实PG分别记录；首批使用合成素材和固定响应fixtures，真实外部状态另填。排序通过不等于教学质量已人工验收。

**Rollback**：默认来源维持原网页入口兼容；可关闭新GitHub/检查入口，保留旧字段和所有新证据数据。已写新记录时不盲目降级DB；代码回退先做兼容检查，不能删除迁移历史。

### N1b：真实GitHub发现、有限章节检查与私人接入

**恢复矩阵**：

| 退出位置 | 预期行为 | 不允许 |

| 尚未派发 | 依据持久记录安全重领 | 同键重复创建业务任务 |

**Rollback**：仅停止本轮拥有的进程/禁用新入口；不清队列、不删attempt/checkpoint/账本、不取消他人任务。持久状态允许后续按安全动作续接。

## 9. XG：GitHub账号连接是独立交付项

公开搜索无需先登录；连接GitHub用于用户身份与授权仓库访问。GitHub App的用户token权限是用户和App权限的交集，不能把“授权登录”和“已安装且能访问该仓库”当同一个状态。[W03][W04]

**Goal / Allowed changes**：在StudyPlan内实现只读GitHub App浏览器授权、固定回调、连接状态、可访问仓库范围与断开；前后端API、按用户加密token存储、必要增量迁移、测试及`.env.example`非秘密说明。

**Constraints / Non-goals**：不实现通用MCP Runtime；不复制Codex插件token；不把历史服务端GITHUB_TOKEN当成所有人的账号；私库不进入公共缓存/Seed；账号授权不默认许可私有内容外发云模型。

使用一次性会话绑定state、S256 PKCE、固定回调白名单与服务端换token；并发刷新有保护；拒绝回调重放/错账号/错state。连接断开立即阻断后续读并处理本地凭证；上游吊销/权限收窄时刷新连接状态，不将授权失败混成“仓库不存在”。实现时核对官方当前API行为。[W04]

**Tests**：拒绝授权、错state、重放、token过期/刷新、撤销、未安装/无仓库权限、跨账号读取与断开、私有内容外发被拦截。最后必须真实浏览器授权→软件显示正确账号/允许仓库→实际读取→断开。仅打开授权网页不算连接成功。

**外部门禁**：维护者已注册App、固定回调与本机秘密配置、用户完成其本人授权。配置缺失时完成代码和契约测试，真实授权NOT RUN，F08的账号连接子项BLOCKED；不删掉该子项。

**Rollback**：禁用连接入口、停止使用凭证并按授权做吊销/删除密钥材料；不影响匿名公开资源/既有合法历史快照。密钥操作不能删用户业务历史。

## 10. XR：独立RAG纯检索与授权契约

**已知边界**：固定交接定位独立工程为 `E:\RAG quention`，三个既有API端口8000/18086/18087；当时health显示cloud_enabled与local_query_enabled均false。在线契约没有明确的独立纯检索endpoint/securitySchemes，StudyPlan虽有配置字段与RAGPort，但没有完成真实接线。未声明securitySchemes本身不能证明全部实际鉴权行为；必须核实运行实现。[S09][S13]

**StudyPlan侧允许改动**：RAGPort的兼容扩展、薄HTTP适配、服务端连接/范围映射、证据展示与降级、契约fixtures与测试。不得把用户登录凭证直接转发给RAG。

**最小契约建议**：认证过的调用方身份、由服务端决定的connection与允许知识库/文档范围、query、limit；结果包含evidence_id/text/source定位/document版本与权限范围的可核实关联。空结果与服务失败分开；无可引用定位的片段不能当作可靠引用。纯检索不得启动回答生成、云端query改写或隐含收费；不能仅发送`allow_cloud=false`字段就假定服务实际执行此语义。

**Tests**：真实允许范围检索且来源可定位、另账号/另知识库拒绝、伪造scope拒绝、空结果、超时/服务断开/引用缺失、学习Summary和进度不回滚；实际调用回执应能证明未触发回答/云调用。Fixture通过不替代这些真实证据。

**Evidence / Rollback**：OpenAPI快照仅为契约证据；health仅为存活。缺条件就F17 BLOCKED、真实检索NOT RUN，其余工作继续。回滚禁用StudyPlan适配，保持RAG独立服务和原数据不动。

## 11. N6：完整验收与本机生产模式交付

默认交付目标先定为**现有Windows本机可持续使用的生产构建**；公网部署不是默认动作，也不把Vite开发/preview服务称为生产部署。沿用已有成熟单机服务/静态资源托管方式，具体启动入口由本机盘点确定，不新建Kubernetes/微服务。[S01][S03]

**Allowed changes**：生产模式启动/升级/停止脚本、构建与健康检查、使用与运维说明、隔离恢复演练、受影响功能修复和验收报告。不修改全局角色、不清正常库、不擅自开放公网端口。

**正常账号闭环**：注册/登录 → 创建项目 → 集中确认目标/Profile → 新Seed生成/草案修改/业务确认 → 学习资料发现和私人替换 → 阶段总结 → 实践/Prompt修订及指定版本导出 → 成果与逐项USER验收 → 阶段完成投影 → Outcome归集 → 重规划与旧版本读取 → 退出重登录继续。用两个账号/多个项目验证所有新对象、历史、下载和RAG证据的隔离。

**恢复演练**：在明确授权、登记的独立新数据库恢复备份，检查Schema/关键关联/计划和历史内容、登录与代表读路径；恢复环境默认关闭真实外部派发和Worker，不消费备份中的旧任务。不能覆盖现有库，不用“压缩包可解压”冒充恢复成功。

**Tests / Evidence**：四层分别记录：规则/Contract/Fake；真实PG；真实外部服务；真实浏览器。Q01–Q12按所有新对象补齐，不沿用与输入/契约已变化的旧PASS。测试只用PASS/FAIL/NOT RUN；功能子项用NOT_STARTED/IMPLEMENTED/VERIFIED/BLOCKED，必须写具体范围。

发布候选记录实际代码SHA、迁移head、Seed版本/hash、前端构建、环境、精确测试命令/退出码、证据路径、授权/用量和已知风险。技术通过与用户主观使用接受分开；不替用户认可，不据测试总数量计算完成度。

**Rollback**：保留先前可用构建、追加式迁移和发布版本；升级前按许可做备份，优先兼容回退或前向修复，不能无条件alembic downgrade。生产数据操作需要其独立授权。

## 12. 预算与真正的外部阻塞

固定交接的最新累计是模型23/50、搜索3/1000（Tavily2+GitHub1），unknown0；README读取另外记2。后文历史记录中的2/1000不能覆盖最新3/1000。执行时以本机最新append-only账本复核，不假定后续没有新增消费。[S01][S13][S14]

开发模型弹性与上述产品/验收计量完全分开。模型失败请求也占请求额度；结果无usage不能猜费用为0。搜索计数、页面/文件读取计数、元数据请求计数、provider实际计费各记各的；更换库/Project/AcceptanceId不能重置既有累计。

第一批默认不增加真实收费模型调用。后续真模型验收须先根据实际调用图估算单目标dispatch上界，核对剩余额度和授权覆盖，再创建新AcceptanceId。原G1一次验收用了20次模型请求的历史记录不等于新三Blueprint可免费重复三遍，也不能只按“3次生成按钮”估计请求数。[S14]

种子命中后的依赖、映射、ID、章节与权限由代码处理；正常生成约2–3次主要模型调用只是既有优化方向，不是当前性能事实或可绕过校验的硬目标。可先离线复用结果测试，实际外部调用仅验证变化的链路，不重复已有效昂贵验证。[S03]

| 事项 | 不等决定就可推进 | 真正不能擅自做的动作 |
|---|---|---|
| GitHub App | 连接代码、加密与回调契约、fixtures | 注册/更改App权限、假填secret、代用户授权 |
| RAG | StudyPlan适配、scope测试、外部窄接口变更说明 | 猜保留实例、改独立工程、复制数据、重启/开云 |
| 付费验收 | 离线/PG/受控HTTP测试、调用预算核对 | 超额度、变更计费渠道、未知结果自动重派 |
| 交付 | 本机生产模式脚本与隔离测试 | 公网发布、购买、正常库破坏性迁移或全局角色更改 |

只暂停受影响支线。已有明确授权无需重复问；缺失内容一次性汇总，不能让Codex通过无限搜索或整套框架迁移替代决策。

## 13. 每批报告与退出标准

每批输出固定为：用户现在新增能做什么；本批Goal及修改范围；实际模型/effort与写入归属；测试表（状态/环境/命令/退出码/SHA/证据路径）；授权用量；未完成/未验证/外部契约缺失/用户决定四类缺口；回滚方式；下一安全动作。

一个样式变更、一个Fake测试或一个健康检查不能触发整项VERIFIED。代码完成但真实条件缺失，保留IMPLEMENTED及相应真实测试NOT RUN，并在子项标BLOCKED。不要仅因不具备外部条件停止其他实现。

首批N1a/N1b完成且门禁满足后，按依赖继续N2/N3；不是每个微小提交都向用户索要继续许可。会话中断时保存当前HEAD、dirty files归属、服务/Worker状态、用量、阻塞和下一安全动作，不承诺工具不支持的后台持续执行。

**时间安排不沿用旧七天承诺，也不据模型档位承诺提前交付。** 本轮只按依赖和实际切片吞吐排序；真实关键路径为资料证据→正式内容/Profile→重规划→恢复/E2E。若RAG外部契约或GitHub授权未就绪，完整READY仍被这些条件阻塞；不能把等用户配置写成“开发已经全部完成”。
