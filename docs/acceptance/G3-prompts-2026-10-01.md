## Implemented / Integrated

位置 CAS 按 project/plan/stage/task 隔离；旧 task 全局 revision_no 唯一约束保留。原文、任务/主项目/知识/来源快照、反馈、导出、绑定与回执不可变。读取最新 20 个修订时，头版本和 ID 窗口使用同一次 SQL 快照；项目历史分页可读旧路线，缺快照的旧数据明确标为 legacy，不补造当时事实。

反馈使用 `prompt.review` / `PromptReviewV1` / `prompt-review-v1`，单 Run 最多 1 次请求，无自动 repair。Summary 与 Prompt 的 queued/running/reconciliation_required 共享每项目 3 个活动反馈上限。已有绑定和回执在配置撤销或新点击键下复用既有 Run；成功响应已入账而业务事务中断时重放保留响应，未知结果进入核对而不再次派发。取消和结果提交共享事务 fence，迟到结果不能覆盖新版或复活取消任务。

本地保存完整冻结要求；模型外发只包含选定原文和必要 task/knowledge 白名单。主项目标题/想法/仓库 URL、资料来源、私有备注、数据库 node_id 等不进入模型上下文。真实 PG sentinel 与离线 wire 测试覆盖该边界。

前端明确区分编辑内容、已保存版本、版本反馈与导出。409、慢 GET、迟到保存及反馈保留本地新编辑；未知请求保留原 body/key，不自动新派发。退出清空内存，不把私有原文写入 localStorage。复制和下载使用服务端返回的指定版本导出。raw 导出上限 40000；实施导出有独立 240000 码点上限，超限明确拒绝，不截断原文。
