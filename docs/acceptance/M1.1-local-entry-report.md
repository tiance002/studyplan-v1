## 最小实现与运行边界

- 新开关 `STUDYPLAN_LOCAL_ENTRY_ENABLED` 默认 false，本次未实际启用。
- 复用 `STUDYPLAN_LOCAL_ACTOR_ID`、`STUDYPLAN_LOCAL_PROJECT_ID`、
  `PLANNING_WORKER_ACTOR_IDS`。缺/占位/含歧义分隔符/不在 worker scope 拒绝。
  PG 适配器在 read-only transaction 中确认准确唯一 actor 和 active owned Project；
  即使查询角色忽略 RLS，Project 查询仍有显式 owner 条件。不会创建 actor/Project。
- `GET /api/v1/session/entry-mode` 只返回模式；
  `POST /api/v1/session/local` 只接受空对象，不接受 token/actor/Project/凭据。
  入口须合法 Origin，创建随机 HttpOnly/SameSite=strict Cookie，并返回既有 CSRF。
  使用原 auth_sessions 表，仅插入自己的新会话；local entry 不清理历史 session。
- 启动拒绝非 loopback APP_HOST、非精确本地 ALLOW_ORIGINS、关闭 CSRF；
  统一 HTTP middleware 检查实际 ASGI peer、精确 Host/端口、Origin、跨站 Fetch Metadata，
  拒绝 Forwarded/X-Forwarded-*，不采纳客户端自报身份。Host 仅允许明确本地 Origin
  authority 与 API 端口上的 localhost/127.0.0.1/[::1]。
- 每次业务访问复核原 actor/Project 绑定；其他 actor 的有效 Cookie 也不能切换身份。
  无 Origin 的 CLI 密码登录保留；后续写必须持有有效 Cookie + CSRF。
  密码认证与 local bootstrap 是两个显式路径，不用 CORS 代替写保护。
- local mode 拒绝注册及旧开发 token 入口；旧 CLI 登录认证继续存在。
  新 session DTO 加入 `default_project_id`。UI local mode 不使用首 Project，
  401 才 bootstrap 一次；绑定错误/403/503 不注册、不 retry，不回退登录页面。
  刷新复用 Cookie。session 422 响应不回显原始输入值。
- `create_app` 的注入测试容器使用其自身 Settings，防止测试意外混用进程部署配置。

实际开启前必须由用户确认原 actor、Project、模型/Run 归属、worker 一致性及监听拓扑。
本实现支持直接本机入口与 loopback 前端代理；任何代理都不能对外暴露，ASGI server
须关闭 proxy-header 信任，避免代理在 middleware 之前改写 peer。APP_HOST 配置检查
不等于已验证真实进程启动参数/监听地址，本次该运行证据 NOT RUN。
本地同机程序具有本机入口权限，不提供对本机恶意进程的隔离。
