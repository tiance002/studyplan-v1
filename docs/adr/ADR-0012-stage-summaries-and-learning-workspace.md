# ADR-0012：阶段总结与学习工作台层级

状态：用户要求已确认，代码与本地集成已实施。日期：2026-10-02。

## 决定

用户最新明确决定：“目前的设计中有总结和实践环节……就够了，同时总结是阶段总结不用每天总结了。”

因此不新增 Exit Criteria、满足 4/5 才继续的通关规则或每天总结要求。保留阶段总结和现有实践任务/成果验收；总结可稍后补写，不阻断学习。

本决定替代 V2 指导 D05/§9.2 中以每次主动结束学习为默认总结触发的安排；原指导保留溯源。总结 API 增量支持 `unit_id` 省略或 null 的阶段位置，明确字符串 unit_id 仍用于旧单元总结和历史，不把旧记录重归属或迁移成阶段总结。

前端阶段与知识节点为父子层级，默认折叠，展开参与正常布局；当前阶段和当前节点采用不同选中态。进度显示仅基于实际记录，不据阅读、勾选或总结自动宣布掌握。

同日后续用户决定：进度界面只显示阶段的已完成/未完成，按阶段总结及既有实践完成记录自动推导，不再展示手动单元进度；资料操作移入三个浮窗。该部分由 [ADR-0013](ADR-0013-automatic-stage-progress-and-resource-dialogs.md) 替代并细化。阶段完成不等于知识掌握核验。

## 课程建议

最小 Agent 后即建立轻量 eval；系统化 Eval/Reward 先于 Agentic RL；RL 基础概念与可选训练实践分开。RAG、状态/编排/恢复按目标决定先后，MCP 按项目需要安排。进阶评估必需 Eval 基础，但无需先完成模型训练。

本轮将课程改进作为独立建议视图展示，未发布或导入新版 Seed，历史已批准路线不在读取时替换。后续课程正式发布须使用新受控版本；自主调整/模型重规划仍按既有预览、新版本与用户确认事务执行。

实施与验证见[学习工作台改版验收](../acceptance/frontend-learning-revision-2026-10-02.md)。本决定不代表完整 V2 Goal 或 milestone 已接受。
