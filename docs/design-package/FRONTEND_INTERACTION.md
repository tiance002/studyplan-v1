# 前端交互契约

2026-10-01 / S0。React 只消费稳定业务 API；布局基线已有 AppShell/panels/ResizableDivider，学习助手/会话尚未可用。

## N / P / C / A

默认 Navigation 11% / Plan 17% / Canvas 72%。打开右侧独立助手 A：折叠 N，形成 P+C+A；用户主动重开 N：折叠 P，形成 N+C+A。A 可拖拽，宽度扩大到挤压 Canvas 时依次折叠左侧。恢复关闭前布局只采用仍满足窗口约束的状态。

桌面 Canvas 目标最小约 600px；窄窗口放不下时降级为 Canvas 优先、侧栏抽屉/单独打开助手，不承诺小于 600px 的屏幕上仍同时展示三区。现有 panels.ts 的小于 960 隐藏 A、小于 760 隐藏 P 为基线；功能切片验证 1366/1440/1920、拖拽和窄窗，必要调整同步测试。

## 节点工作区

围绕当前知识节点展示当前目标、为什么学、前置/核心/子知识、资料、思考问题、总结/反馈、任务和阶段成果。选中节点和 plan_version 共同决定 Canvas 与助手上下文；导航不能伪造节点已学会。

助手不是浮窗。输入绑定 current_node_id、plan_version_id、session_id 和服务端 scope；显示正在讨论的知识目标。切节点时恢复对应 Session；等待中的回答仍保存到发送时的上下文，不误挂到新节点。旧 Session 按历史版本恢复并明确标记。

## 用户决定与异常

Draft 显示结构/资料/任务、核验限制、approve/edit/cancel。决定提交 expected_version/hash/idempotency_key；等待期间防重复，失败保留编辑。结构调整显示差异和新版本，需用户确认。

反馈中的理解问题、实践状态、证据等级和节点状态用不同文案；不能把 prompt_reviewed、任务提交、单元 completed 展示成知识已核验。资源不可达、缺引用、provider 未知分别显示可采取动作。

## 视觉与本地入口

暖白、石墨灰、克制强调色、内容优先；沿用可用工作区。M1.1 完成后本地用户直接进入自己的学习空间，不把注册登录作为学习门槛；当前认证实现的迁移边界见 ADR-0007，不先移除底层 scope/数据保护。
